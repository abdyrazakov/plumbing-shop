# Design: Initial Django Scaffold

## Overall project layout

```
plumbing-shop/
├── manage.py
├── requirements.txt
├── shop/              # Django project (settings, urls, wsgi/asgi)
│   ├── __init__.py
│   ├── settings.py
│   ├── urls.py
│   ├── wsgi.py
│   └── asgi.py
└── catalog/           # Django app (models, admin)
    ├── __init__.py
    ├── apps.py
    ├── models.py
    ├── admin.py
    ├── migrations/
    │   └── __init__.py
    ├── views.py       # left as default stub, no views yet
    └── tests.py       # left as default stub
```

SQLite (`db.sqlite3`) is the default DB via Django's default settings — no changes needed beyond what `startproject` generates.

## Files this ticket touches

- **`requirements.txt`** — pin `Django` to a specific current stable version (e.g. `Django==5.1.x`).
- **`manage.py`, `shop/settings.py`, `shop/urls.py`, `shop/wsgi.py`, `shop/asgi.py`** — generated by `django-admin startproject shop .`; in `settings.py` add `'catalog'` to `INSTALLED_APPS`. No other settings changes needed (SQLite is default).
- **`catalog/apps.py`** — generated by `startapp`; defines `CatalogConfig`.
- **`catalog/models.py`** — define:
  - `Category`: `name` (CharField).
  - `Product`: `name` (CharField), `description` (TextField), `price` (DecimalField), `image` (ImageField), `category` (FK → Category), `stock_quantity` (IntegerField).
  - `OrderRequest`: `product` (FK → Product), `customer_name` (CharField), `phone` (CharField), `quantity` (PositiveIntegerField), `created_at` (DateTimeField, auto_now_add).
- **`catalog/admin.py`** — register `Category`, `Product`, `OrderRequest` with `admin.site.register(...)` (plain registration, no custom ModelAdmin yet — owner just needs to add/edit via admin).
- **`catalog/migrations/0001_initial.py`** — generated by `makemigrations`, not hand-written.

## Notes

- `ImageField` requires `Pillow` — add it to `requirements.txt` alongside Django.
- No views/urls/templates are needed for this ticket — catalog display and the order form come later.
- Validate with `python manage.py check` and `python manage.py makemigrations` before considering the ticket done.

## Ticket: public views and templates

Server-rendered, minimal-CSS public pages: home (category list), catalog (products filtered by category), product detail. No JS framework, no forms/auth yet — read-only browsing.

### Files this ticket touches

- **`catalog/views.py`** — add three function-based views:
  - `home(request)` — queries all `Category` objects, renders `catalog/home.html` with `categories`.
  - `catalog_view(request, category_id)` — `get_object_or_404(Category, pk=category_id)`, queries `Product.objects.filter(category=category)`, renders `catalog/catalog.html` with `category` and `products`.
  - `product_detail(request, product_id)` — `get_object_or_404(Product, pk=product_id)`, renders `catalog/product_detail.html` with `product`.
- **`catalog/urls.py`** (new) — app-level urlconf:
  - `path('', views.home, name='home')`
  - `path('catalog/<int:category_id>/', views.catalog_view, name='catalog')`
  - `path('product/<int:product_id>/', views.product_detail, name='product_detail')`
- **`shop/urls.py`** — add `path('', include('catalog.urls'))` (keep `admin/` as-is).
- **`catalog/templates/catalog/base.html`** (new) — shared layout: `<head>` with a link to `{% static 'catalog/style.css' %}`, a simple header with a link back to `home`, and a `{% block content %}`.
- **`catalog/templates/catalog/home.html`** (new) — extends `base.html`; lists `categories`, each linking to `catalog` with its `category.id`.
- **`catalog/templates/catalog/catalog.html`** (new) — extends `base.html`; shows `category.name` as heading, grid/list of `products` (name, price, thumbnail), each linking to `product_detail`; link back to home.
- **`catalog/templates/catalog/product_detail.html`** (new) — extends `base.html`; shows product image, name, description, price, stock_quantity; link back to its category's catalog page.
- **`catalog/static/catalog/style.css`** (new) — minimal plain CSS (layout spacing, a simple grid for product cards, no framework).
- **`shop/settings.py`** — add `MEDIA_URL = 'media/'` and `MEDIA_ROOT = BASE_DIR / 'media'`; in dev, product images are only served without a dedicated webserver if `shop/urls.py` also appends `static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)` when `DEBUG` is `True` — add that too, since templates render `product.image.url`.

### Notes

- Keep templates logic-light: querying/filtering stays in views, templates just loop and display.
- No pagination, search, or cart/order-form UI in this ticket — that's for a later ticket (`OrderRequest` already exists in models but has no form yet).
- Validate with `python manage.py check` and by running the dev server and clicking through home → catalog → product detail.

## Ticket: order-request form on product detail page

Customer can request to order a product from the product detail page by
submitting `customer_name`, `phone`, `quantity`. On valid submit, create an
`OrderRequest` row (model already exists, see above) and show a thank-you
page. Standard POST → validate → save → redirect (PRG) flow; invalid
submissions re-render the detail page with field errors.

### Files this ticket touches

- **`catalog/forms.py`** (new) — `OrderRequestForm(forms.ModelForm)`:
  - `Meta.model = OrderRequest`, `Meta.fields = ['customer_name', 'phone', 'quantity']`.
  - `clean_phone()` — strip whitespace, validate against a permissive phone
    regex (digits, optional leading `+`, spaces/`-`/`()` separators, 7–15
    digits total); raise `ValidationError` with a user-facing message if it
    doesn't match.
  - `quantity` already uses `PositiveIntegerField` on the model, which
    rejects zero/negative/non-integer input with Django's built-in
    validation message — no extra `clean_quantity` needed.
- **`catalog/views.py`** — update `product_detail(request, product_id)`:
  - On `GET`: build an unbound `OrderRequestForm()`, render as before with
    `form` added to context.
  - On `POST`: build `OrderRequestForm(request.POST)`; if `form.is_valid()`,
    set `order_request.product = product` via `form.save(commit=False)`,
    save, then `redirect('order_thanks', order_id=order_request.id)`. If
    invalid, re-render `product_detail.html` with `form` (containing
    errors) and `product`.
  - Add `order_thanks(request, order_id)` — `get_object_or_404(OrderRequest, pk=order_id)`, renders `catalog/order_thanks.html` with `order_request`.
- **`catalog/urls.py`** — add `path('order-thanks/<int:order_id>/', views.order_thanks, name='order_thanks')`.
- **`catalog/templates/catalog/product_detail.html`** — add a `<form method="post">` block below product info: `{% csrf_token %}`, render `form` fields (non-field and per-field errors shown), submit button labeled e.g. "Request to order".
- **`catalog/templates/catalog/order_thanks.html`** (new) — extends `base.html`; simple confirmation message (e.g. "Thanks, {{ order_request.customer_name }} — we'll contact you about {{ order_request.product.name }}"), link back to the product or home.

### Notes

- Validation lives in the form (`clean_phone`) and model field
  (`PositiveIntegerField` for `quantity`), not in the view — keeps the view
  thin and errors reusable if a second entry point is added later.
- No AJAX/JS — plain form POST with full-page reload, consistent with the
  rest of the site (no JS framework per the public-views ticket).
- Validate with `python manage.py check` and by submitting the form with
  valid input, a bad phone number, and a zero/negative quantity.

## Ticket: tests for models, order-request form, and submission flow

Django `TestCase` coverage for what's been built so far: the three models,
`OrderRequestForm` validation, and the end-to-end POST-creates-order flow
on `product_detail`.

### Files this ticket touches

- **`catalog/tests.py`** — replace the stub with test classes (plain
  `tests.py` is fine at this size; no need to split into a `tests/`
  package yet):
  - `CategoryModelTests` — creates a `Category`, asserts it saves and
    `str(category)` returns its name (if `__str__` is defined; otherwise
    just assert the saved instance's `name` field).
  - `ProductModelTests` — creates a `Category` then a `Product` referencing
    it, asserts fields round-trip (`name`, `price`, `stock_quantity`,
    `category`) and that `product.category == category`.
  - `OrderRequestModelTests` — creates `Category` → `Product` →
    `OrderRequest` referencing the product, asserts fields round-trip and
    `created_at` is auto-populated (`auto_now_add`), and that
    `order_request.product == product`.
  - `OrderRequestFormTests` — using a `Product` created in `setUp`:
    - valid case: data with well-formed `customer_name`, `phone` (e.g.
      `"+1 555-123-4567"`), `quantity` (e.g. `2`) → `form.is_valid()` is
      `True`.
    - invalid phone: data with a `phone` that fails the `clean_phone`
      regex (e.g. letters, or too short) → `form.is_valid()` is `False`
      and `'phone'` is in `form.errors`.
    - invalid quantity: `quantity` of `0` or `-1` → `form.is_valid()` is
      `False` and `'quantity'` is in `form.errors` (exercises the model's
      `PositiveIntegerField` validation surfaced through the form).
    - missing required field (e.g. blank `customer_name`) → `form.is_valid()`
      is `False` and `'customer_name'` is in `form.errors`.
  - `OrderRequestSubmitViewTests` — using a `Category`/`Product` created in
    `setUp` and Django's test `Client`:
    - valid POST to the `product_detail` URL (`reverse('product_detail',
      args=[product.id])`) with valid `customer_name`/`phone`/`quantity` →
      asserts an `OrderRequest` row was created (`OrderRequest.objects.count()`
      increases by 1, and the created row's `product` matches), asserts the
      response is a redirect (302) to the `order_thanks` URL for the new
      order's id, then follows the redirect and asserts the thank-you page
      renders with status 200 and contains the customer's name (or use
      `follow=True` on the POST and assert the final rendered content
      instead of a separate GET).
    - invalid POST (e.g. bad phone) → asserts no new `OrderRequest` was
      created, response status is 200 (re-renders `product_detail.html`,
      no redirect), and the response contains the form's error text.

### Notes

- All tests use Django's `TestCase` (not `SimpleTestCase`), since every
  test touches the DB.
- No new fixtures/files needed — `setUp` builds the small object graph
  (`Category` → `Product` → optionally `OrderRequest`) each test class
  needs directly.
- Run with `.venv/bin/python manage.py test catalog` (see Environment
  note below for why the venv matters).

## Ticket: visual fixes from Designer review (VISUAL: FAIL)

Designer reviewed screenshots of home/catalog/product/thanks and flagged four
concrete defects. This ticket fixes all four without re-skinning the site —
the existing visual language (teal `--color-primary` `#0f5f66`, orange
`--color-accent` `#e07a3f`, "Source Sans 3", `10px` radius, existing
`--shadow`/`--shadow-hover`) stays; only the flagged elements change. Consulted
`frontend-design` for direction before touching any template/CSS; the
resulting choices below stay inside the current palette/type system rather
than introducing a new one, since only these four elements were flagged.

### Design direction (from frontend-design skill pass)

- **New/adjusted tokens in `style.css`** (additive, no existing var renamed):
  - `--color-success: #3f7a56` — single success color, replacing the two
    inconsistent greens currently hardcoded (`#4a7c59` on the thanks badge,
    `#2f6b45`/`#e8f3ec` on the in-stock pill); both should read off this one
    var (plus a light tint for backgrounds, e.g. `--color-success-tint:
    #e7f2ea`).
  - `--color-placeholder-bg: #dde3e8` / `--color-placeholder-icon: #96a3af` —
    a neutral slate pair, deliberately *not* teal or orange, so placeholder
    images read as "no photo yet" rather than as a branded/decorative tile.
  - `--content-max-width: 1160px` — one var, used by both
    `.site-header-inner` and `.site-content` (currently both hardcode
    `1080px` separately). Modest bump, not a full-bleed redesign — gives the
    heavier category cards/icons room on wide screens while keeping line
    lengths reasonable.
- **Thanks-page badge**: the bare `✓` text glyph is the one bold moment on
  that page (per "spend your boldness in one place") — make it a real
  anchor: a `72px` circle in `--color-success`, checkmark drawn as two
  `::before`/`::after` bars (rotated rectangles, classic CSS-checkmark
  technique) in white — no Unicode glyph, no font rendering risk. Give it
  one deliberate shadow (`0 6px 18px rgba(63,122,86,.35)`) since this is the
  single spot on the page that earns one, and tighten the margin to the
  heading so it reads as anchoring it, not floating above it.
- **Home category cards**: add an icon tile (44–48px rounded square, tinted
  `--color-primary` background, a single consistent inline SVG glyph in
  `currentColor` — reuse the wrench/droplet motif already in the header
  logo rather than inventing a second icon family) above the category name.
  Restyle the existing `category.product_count` line (already in context —
  `views.py`'s `home()` already annotates it via `Count('product')`, no
  view change needed) as a small styled line instead of plain muted text.
  Extend the existing `:hover` transition to also shift the icon tile
  toward the accent color, on top of the current lift/shadow, so hover
  reads as one coordinated state change, not a bolt-on.
- **Placeholder images** (`seed_demo.py`): drop the PIL text rendering
  entirely. Draw a flat `--color-placeholder-bg`-tint rounded rect with a
  simple centered "image placeholder" glyph in `--color-placeholder-icon`
  (basic shapes only — e.g. a frame + small circle + triangle, the
  conventional "image" icon) — no product name, no font dependency.
- **Shared container**: `base.html`'s `.site-content` already centers via
  `margin: 0 auto`, but it and `.site-header-inner` each hardcode their own
  `1080px` — consolidate both onto the one `--content-max-width` var so
  there's a single source of truth all four pages inherit, and audit
  `product_detail.html` (`.product-detail` grid, `.order-form` max-width)
  and `order_thanks.html` (`.success-panel` max-width) to confirm their
  inner elements sit inside that shared shell rather than pinning narrow
  content to the left edge of it.

### Files this ticket touches

- **`catalog/static/catalog/style.css`** — add the tokens above; consolidate
  `.site-header-inner`/`.site-content` onto `--content-max-width`;
  redesign `.category-card` (icon tile, restyled count line, coordinated
  hover state); replace `.success-panel .success-icon`'s glyph rendering
  with a CSS-only checkmark (`::before`/`::after`) and size/shadow per
  above; add placeholder-tint styling if the `<img>` needs a fallback frame
  (optional — primary fix is in `seed_demo.py`, see below).
- **`catalog/templates/catalog/home.html`** — add the inline SVG icon
  markup inside each `.category-card`, before `.category-card-name`; wrap
  `category.product_count` in the restyled count element. No new context
  needed from the view.
- **`catalog/templates/catalog/order_thanks.html`** — replace
  `<div class="success-icon">✓</div>` with CSS-only badge markup (empty
  element(s) for the `::before`/`::after` bars, no Unicode character).
- **`catalog/templates/catalog/base.html`** — no structural change beyond
  whatever the `--content-max-width` consolidation requires; confirm both
  `.site-header-inner` and `.site-content` reference the shared var.
- **`seed_demo.py`** — rewrite `placeholder_image()`: drop `ImageFont`/
  `FONT_PATH`/`draw.text(...)` entirely; draw the flat-tint rect + simple
  icon-style glyph instead (PIL shape primitives only, no text, no font
  file dependency). After the change, **re-run it**
  (`.venv/bin/python seed_demo.py`) so the existing demo products' stored

### Notes

- No new image assets, icon libraries, or JS — inline SVG / CSS-drawn
  glyphs only, consistent with the rest of the site.
- Keep the palette/type system as-is; this ticket is corrective (4 named
  defects), not a re-skin.

## Ticket: round-2 visual fixes from Designer review (VISUAL: FAIL)

A follow-up review of the ticket-4 fixes flagged five more concrete defects,
confirmed against real screenshots of home/catalog/product/thanks with
seeded data (see `design_review/*.png`). Corrective only — same palette/type
system as before (teal `--color-primary`, orange `--color-accent`, "Source
Sans 3", `10px` radius, existing `--shadow`/`--shadow-hover`). Consulted
`frontend-design` before touching template/CSS; because this is a corrective
pass on an already-established system (not a new design), the direction is
to keep every fix inside the existing token set and only touch the five
flagged elements — no new palette, no new type scale.

### Design direction (from frontend-design skill pass)

- **Category icons are real photos, not glyphs** — `pipes.jpg`/`faucet.jpg`/
  `toilet.jpg`/`heater.jpg` carry their own color/lighting, so the old
  "24px `currentColor` SVG in a 46px tinted tile" treatment (designed for a
  flat single-color glyph) doesn't fit. Drop the tint-background-on-hover
  trick entirely; treat the icon tile as a small photo thumbnail instead —
  bump it to a `56px` rounded-`8px` square, `object-fit: cover`, plain
  `var(--color-border)` outline so it reads as a product photo chip, not a
  colored icon. The card's existing lift+shadow hover (`:hover` → `translateY(-2px)`
  + `--shadow-hover`) is enough of a hover state on its own; no
  icon-specific hover change needed once the icon is a photo.
- **Placeholder swap stays purely structural** — no new visual treatment to
  design; `placeholder.jpg` already exists and matches the
  `--color-placeholder-bg`/`--color-placeholder-icon` pair from the prior
  ticket. This is a wiring fix (static fallback instead of a per-product
  generated file), not a new design decision.
- **Pluralization and dead-space fixes are non-visual/structural** — no new
  tokens; the footer gap is fixed by making the footer stick to the bottom
  of the viewport for short pages (classic sticky-footer flex pattern)
  rather than leaving the page's gray background end abruptly above a
  blank browser background, which is what currently reads as a "dead gap."
- **Order-form column alignment**: the form card's independent
  `margin: 0 auto` is the bug — it should simply inherit the container's
  left edge like `.product-detail` already does, not be centered as its own
  unit. Drop the auto-centering; keep its existing `max-width: 420px` so it
  doesn't stretch full-width on desktop.

## Environment note

A virtualenv already exists at `.venv`, built with Python 3.11 (not the
system default 3.14 - Django's test client breaks under 3.14's new `copy`
semantics). Always run project commands through it: `.venv/bin/python
manage.py ...`, `.venv/bin/pip install ...`. Do not recreate `.venv` with
a different Python unless you also reinstall `requirements.txt` into it.
