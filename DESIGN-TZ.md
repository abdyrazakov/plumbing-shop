# ТЗ: редизайн витрины «СантехМаркет»

**Роль:** дизайнер / фронтенд-разработчик (HTML + CSS, минимальный JS).
**Цель:** сделать витрину современной, аккуратной и удобной, не меняя логику бэкенда.
**Репозиторий:** https://github.com/abdyrazakov/plumbing-shop (публичный, ветка `master`).
**Срок:** 1–2 недели на первый проход (P0), дальше — итерации.

---

## 1. Что это за проект

Небольшой интернет-магазин сантехники в Бишкеке. Покупатель выбирает товары, складывает в корзину и оставляет одну заявку (имя + телефон). Оплаты и доставки на сайте нет — заказ подтверждают по телефону/WhatsApp.

**Стек:** Python 3, Django 5.1.15, SQLite, Django-шаблоны, один CSS-файл. Никаких JS-фреймворков, сборки и npm.

**Запуск:**

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python seed_demo.py          # демо-товары, пересоздаёт данные
python manage.py createsuperuser
python manage.py runserver
```

Главная: http://127.0.0.1:8000/ · админка: http://127.0.0.1:8000/admin/

## 2. На каком этапе проект

MVP готов и работает:

- главная с категориями;
- каталог по категориям и карточка товара;
- корзина в сессии (добавить / изменить / удалить);
- оформление заказа с валидацией телефона и страницей подтверждения;
- настроенная админка (русские подписи, статусы остатка, фильтры, превью фото);
- 59 автотестов проходят.

То есть **всё функциональное уже есть** — не хватает визуального качества и UX-полировки. Скриншоты текущего состояния лежат в `design_review/` (`home.png`, `catalog.png`, `product.png`, `thanks.png`).

## 3. Границы ответственности

### Можно менять

- `catalog/templates/catalog/*.html` — разметка и классы;
- `catalog/static/catalog/style.css` — основной файл стилей;
- `catalog/static/catalog/` — новые картинки, SVG-иконки, шрифты, небольшой JS-файл;
- `templates/admin/base_site.html` — только если правка не ломает админку.

### Нельзя менять без согласования

- `catalog/views.py`, `catalog/models.py`, `catalog/forms.py`, `catalog/cart.py`, `catalog/urls.py`, `shop/settings.py`;
- миграции, `requirements.txt`, логику корзины и заказа;
- `catalog/tests.py` (тесты — контракт поведения);
- `DESIGN.md`, `factory_log.json` — внутренние артефакты, не трогать.

### Бэкенд — только при найденной ошибке

Если для дизайна не хватает данных (например, нужен артикул, старая цена, число отзывов) — **не добавляй сам**. Опиши в PR/issue, что нужно, и предложи минимальный патч. Владелец решит.

Если нашёл реальный баг (500, неверная сумма, товар не добавляется) — заведи issue с шагами воспроизведения, не смешивай с дизайн-PR.

**Обязательно:** после любых правок `python manage.py test` должен оставаться зелёным (59 тестов).

## 4. Аудит текущего дизайна

Проверь сам, но вот что видно сразу:

1. **Главная** — текстовый hero на плоском фоне без визуального якоря и без явного CTA. Нет ощущения «магазина», скорее лендинг-заготовка.
2. **Иконки категорий** — растровые JPG (`pipes.jpg`, `faucet.jpg`, `toilet.jpg`, `heater.jpg`), разного качества и стиля, выглядят устаревшими и мылятся на Retina.
3. **Trust strip** — четыре пункта в строку, на мобиле складываются в столбик и выглядят как список.
4. **Бренды** — просто текстовые слова; доверия не добавляют.
5. **Карточки товаров** — только тень при наведении, нет статуса наличия, нет аккуратной цены, кнопка «В корзину» визуально оторвана от карточки.
6. **Карточка товара** — блок добавления в корзину вынесен *под* описание отдельной формой; нет галереи, блока доставки/гарантии, внятной иерархии.
7. **Корзина** — кнопка «Обновить» рядом с полем количества (лишний шаг), нет липкого итога, на мобиле строки рвутся некрасиво.
8. **Типографика** — 3 начертания без системы масштабов; заголовки и текст почти одного веса.
9. **Состояния** — почти нет `:focus-visible`, нет `prefers-reduced-motion`, нет внятных hover/active/disabled.
10. **Анимации** — фактически отсутствуют.
11. **Мета** — нет favicon, `description` и Open Graph (ссылка в мессенджере выглядит пустой).
12. **Хедер** — не липкий, на узких экранах элементы переносятся неаккуратно.

Палитра (тёмно-бирюзовый `#0f5f66` + оранжевый `#e07a3f`) рабочая — её можно сохранить и доработать, а не менять с нуля.

## 5. Задачи

Приоритеты: **P0** — обязательный первый проход, **P1** — желательно, **P2** — если останется время.

### P0. Дизайн-система и база

- Привести `style.css` к токенам: шкала отступов (4/8/12/16/24/32/48/64), шкала типографики, радиусы, тени, цвета, тайминги анимаций. Всё — через CSS-переменные в `:root`.
- Подключить нормальный шрифт с кириллицей (текущий Source Sans 3 можно оставить, но проверить веса и загрузку; альтернативы: Manrope, Inter, Golos Text).
- Добавить `:focus-visible` для всех интерактивных элементов, `:hover`/`:active`/`:disabled` состояния.
- Добавить `@media (prefers-reduced-motion: reduce)` — отключать все анимации.

**Приёмка:** стили не дублируются, магические числа заменены токенами, клавиатурная навигация видима.

### P0. Главная страница

Структура сверху вниз:

1. **Hero** — не просто текст: фон/фото сантехники или аккуратная композиция, заголовок, подзаголовок, 1–2 CTA («Смотреть каталог», «Связаться в WhatsApp»), визуальный акцент. Высота — не на весь экран, на мобиле — компактно.
2. **Trust strip** — 4 преимущества в виде карточек с иконками, сетка 4 → 2 → 1.
3. **Категории** — крупные карточки, векторные иконки (SVG) вместо JPG, счётчик товаров, hover-состояние.
4. **Популярное / витрина товаров** — опционально, если можно получить данные без правок бэкенда (например, через существующий контекст нельзя — тогда пропустить и отметить в PR).
5. **Бренды** — нейтральные бейджи/логотипы, без «просто текста».
6. **Финальный CTA-блок** — «Не нашли нужное? Напишите в WhatsApp».

**Приёмка:** главная продаёт категорию, а не абстрактный текст; на 360 px нет горизонтального скролла; первый экран не перегружен.

### P0. Карточки товаров (каталог)

- Единый аспект изображения (например, 4:3), `object-fit: cover`, аккуратный фон для товаров без фото.
- Название — 2 строки максимум, цена — акцентная и крупная.
- Бейдж наличия: «В наличии», «Мало» (`is_low_stock`), «Под заказ» (`stock_quantity == 0`).
- Кнопка «В корзину» — часть карточки, на мобиле всегда видима (не только по hover).
- Hover: подъём + тень + лёгкий зум фото, 150–250 мс.

**Приёмка:** сетка ровная при 1, 2, 3, 4 товарах; карточки не «прыгают»; текст не выходит за границы.

### P0. Карточка товара

- Двухколоночный макет: слева фото (с местом под галерею), справа — название, цена, наличие, описание.
- Блок покупки (количество + «В корзину») — **рядом с ценой**, а не отдельной формой внизу.
- Количество — степпер «− 1 +» (можно на CSS/минимальном JS, без библиотек).
- Вторичное действие — «Написать в WhatsApp» с предзаполненным текстом (уже есть в шаблоне).
- Короткий блок доверия: доставка, гарантия, самовывоз.

**Приёмка:** добавление в корзину доступно без прокрутки на десктопе и в пределах первого экрана на мобиле.

### P0. Корзина

- Количество — степпер, обновление без лишней кнопки «Обновить» (либо авто-сабмит, либо кнопки «−/+» с отправкой формы).
- Итог — заметный, на десктопе липкий в колонке справа, на мобиле — сверху/снизу секции.
- Мобильная версия — карточки, а не сжатые строки.
- Пустое состояние — иконка, текст, CTA «Перейти в каталог».

**Приёмка:** корзина читается на 360 px; итог всегда виден; ошибки формы заметны.

### P0. Хедер, футер, мета

- Липкий хедер с корректным поведением на мобиле (не прыгает, не перекрывает контент).
- Иконки SVG в едином стиле, корзина с бейджем количества.
- Favicon, `<meta name="description">`, Open Graph (`og:title`, `og:description`, `og:image`) — без правок бэкенда, статичные значения.
- Футер: аккуратная сетка, контакты, часы, ссылки.

### P1. Страница «Спасибо»

- Анимированная галочка, номер заказа, состав, кнопка «Вернуться в каталог».
- Убедиться, что подставляется имя клиента и позиции.

### P1. Доступность

- Контраст текста ≥ 4.5:1, крупного ≥ 3:1.
- `alt` у содержательных изображений, `aria-hidden` у декоративных.
- Порядок фокуса логичный; формы с `label` (уже есть).
- Не полагаться только на цвет для статуса наличия (текст + иконка/форма).

### P2

- Тёмная тема (только если владелец попросит).
- Skeleton-состояния не нужны — рендеринг серверный.
- Микроанимация счётчика корзины при добавлении.

## 6. Анимации

Правила:

- Только осмысленные: появление, hover, нажатие, смена состояния, успех. Не «анимация ради анимации».
- Длительность 150–300 мс, `ease-out` для появления, `ease-in-out` для трансформаций.
- Анимировать только `transform` и `opacity` (не `width/height/top/left`).
- Без layout shift и без «прыжков» при загрузке.
- Обязательный `prefers-reduced-motion`.
- JS — только ванильный, ≤ 5 КБ, без библиотек. Всё, что можно сделать на CSS, делать на CSS.

Идеи: hover карточек, плавное появление секций при скролле (IntersectionObserver), пульс бейджа корзины, галочка на странице «спасибо», мягкий переход для сообщений об ошибках/успехе.

## 7. Технические требования

- Только Django-шаблоны: не ломать `{% url %}`, `{% csrf_token %}`, имена полей форм, `name="quantity"`, `name="next"`.
- Не менять структуру POST-запросов — иначе отвалится бэкенд и тесты.
- Адаптив: 360, 768, 1024, 1440 px. Никакого горизонтального скролла.
- Браузеры: последние Chrome, Firefox, Safari, Edge.
- Без CDN, кроме шрифтов; без тяжёлых библиотек и иконочных шрифтов.
- Изображения — WebP/AVIF где возможно, SVG для иконок, разумный вес.
- Не коммитить `db.sqlite3`, `media/`, `.venv/`, логи.
